# UNI2Blacklist

Windows GUI 黑名单插件，当前版本 `0.1.0-candidate.3`，针对**黑名单为空快速匹配闪退**的诊断候选版。按完整 SteamID64 过滤匹配候选、房间事件及 Steam 通信；原游戏 EXE 和 Steam DLL 的磁盘文件不改写。

**真实 Windows 闪退的根因尚未定位，也未证明已经消除。** 用户报告 candidate.2 黑名单为空快速匹配两三秒后游戏退出、搜索计数1；云端未运行原游戏。新版缩减观察模式的挂钩范围、移除搜索中的额外 Steam 查询，并保留退出证据。[修正与未知点](docs/QUICK_MATCH_CRASH.zh-CN.md)、[验证范围](docs/VALIDATION.zh-CN.md)、[原生接口合同](docs/NATIVE_CONTRACT.zh-CN.md)。旧版本及下载保留，不建议继续用 candidate.2 重复触发该闪退。

## 下载及使用

从仓库 Releases 下载 `UNI2Blacklist-0.1.0-candidate.3-win32.zip`，完整解压，不要在 ZIP 内运行。静态链接运行库，无需安装 Python。

1. **关闭旧黑名单窗口并重启游戏一次**；关闭 GUI 不卸载已注入 DLL，升级不能在同一游戏进程热替换。名单文件沿用。通过 Steam 正常启动游戏，运行 `UNI2Blacklist.exe`，选择进程并点击“连接并启用”。权限应与游戏一致。
2. 首先保持黑名单为空进入快速匹配。此时应显示观察模式；新启动的进程 `hooks_ready=0`、`native_filter_active=0`、`effective_enabled=0` 正常，表示没有安装通信挂钩，**不表示安装失败**。仅搜索观察入口已接入。关闭保护开关也不进行过滤。
3. 窗口按游戏自然搜索结果显示 SteamID64 和 LobbyID。**本轮停用额外 Steam 元数据查询，玩家名、路径估计延迟、实测 RTT、丢包率暂显示“未知”。** 不编造数值，不另外扫描或探测玩家。
4. 玩家最后一次被游戏搜索返回后在 GUI 保留 **120秒**。列表去重依据完整 SteamID64，保持行序和选中账号；“本次返回”与“最近出现”区分最新结果和历史行。历史行不代表玩家仍在待机，**不会重新写回游戏的匹配候选**。每次真实重现才延长保留时间，界面重绘不会延长。
5. 选中玩家点击“拉黑选中玩家”，或手动输入完整十进制 SteamID64 及备注。名单立即保存到 `%LOCALAPPDATA%\UNI2Blacklist\blacklist.tsv`。再次打开恢复名单。首次启用非空黑名单后，控制线程才安装房间及两套通信挂钩；控制周期约100毫秒。安装齐全并满足策略确认、心跳、非战斗条件后 `effective_enabled=1`。这是实现状态，不代表已完成真实联机拒绝验收。
6. 移除账号、关闭开关或关闭窗口会停止相应过滤；已经安装的挂钩仍保留并调用原函数，直到游戏退出。窗口异常退出后，GUI 心跳过期最多10秒后停止过滤。
7. 若游戏再次退出，**不必赶在退出前点击保存**。GUI 保留最后可用状态，自动写入 `%LOCALAPPDATA%\UNI2Blacklist\diagnostics\uni2-<PID>-status.txt`；同目录的 `uni2-<PID>-fault.bin` 是最多512字节的本地异常环形记录。仍可点击“保存诊断状态”导出包含异常信息的文本。自动保存失败会提示，可手动重试。

已有战斗（已查场景1）暂停拦截，对战中添加的名单用于后续匹配。历史列表最多2048人，满时保留现有未过期行并报告省略的新行；每次原搜索快照最多128人，过滤最多检查4096个原候选。

排位匹配玩家随游戏搜索结果动态变化；`candidate_count` 是本次捕获人数，`blacklist_count` 是本地已拉黑账号数。**匹配列表当前无人不停止观察，也不使已保存的黑名单失效。** 通信挂钩延后安装仅取决于保存的黑名单为空/关闭，而不是匹配候选人数为0。最近出现的历史行只便于选择，不能当作当前等待池。

## 诊断含义

- 报告区分界面请求开关、原生入口过滤、完整保护，以及 `connected`、`snapshot_source`。游戏退出后保留旧安装位，但两个有效保护字段强制为0，不能把旧状态当作当前保护。
- `hooks_ready` 是已经安装的通信接口位掩码：1=旧 P2P，2=Messages002，3=两者。首次黑名单为空连接应为0；曾添加名单后清空，位可以仍为3，但有效过滤为0。
- 报告含 PID、搜索次数、最后场景、进程退出码，以及本地异常代码、指令地址、故障地址、线程、阶段和可识别模块名/RVA。模块缓存来自连接时，晚加载或动态代码可能只显示地址与分配基址。
- 异常记录是**第一时间观察到的异常，未必致命**；记录后总继续原异常分发，不恢复故障、不吞掉异常，也不替换游戏的异常处理器。最近8条循环覆盖，不包含堆转储、完整寄存器、堆栈内容或玩家账号。强制终止、部分 fail-fast、栈损坏及记录文件失败可能没有异常条目；没有条目不代表没有崩溃。
- 诊断文本不输出名单账号、玩家名、IP；连接错误可能含本机路径。全部数据只存本地，插件没有日志上传功能。本项目不修改注册表、Windows 防火墙或系统错误报告设置。

## 过滤边界

搜索仍受原游戏区域、距离、模式和数量限制，不能保证显示全部在线或待机玩家。按账号而非全系统 IP 拦截；Steam 中继 IP 可能共享。丢弃黑名单消息的计数不是网络丢包率。

忽略 entered 事件不会强踢 Steam 后端房间里的玩家，对方可能占用槽位直到原清理或超时。名单在已有确认/握手后添加不会撤销已发生的界面切换；所有匹配模式是否能在确认阶段前拒绝仍待用户实测。与 uniGGPO 等其他注入插件同时运行尚未验证。

支持的版本固定为：

| 文件 | SHA-256 |
| --- | --- |
| `uni2.exe`（6,921,216字节，PE32） | `cf64ec26e9646b68b46ed22c838b8f0778ab65abbeda0ebf164e81b5c08c9098` |
| `steam_api.dll` | `67ae11d71ae6ec404090094df1e47b614d27400dc53fa450023e6fbcf347902c` |

其他版本拒绝连接；已改动的游戏入口会被签名校验拒绝。

## 原理及构建

GUI 核验目标文件与运行映像，在目标进程调用 Windows `LoadLibraryW` 加载 DLL、调用 `BlacklistStart` 初始化；同用户本机共享内存与互斥量传递策略和候选快照。原搜索调用完成后，搜索挂钩在同一生产线程、原 completion 回调之前检查快照；只有确有拉黑候选时才压缩游戏可见索引。候选缓存放在堆上，额外处理与原游戏调用分开。

原游戏入口及旧 P2P 使用固定版本 MinHook，保留原函数 trampoline；现代 Messages002 原子替换原虚函数表的 slot0/1/2，保留原表、RTTI、其他公开/隐藏方法和各原函数。页权限恢复、比较交换、部分回退和归属检查失败时锁存错误并停止过滤。本轮首次黑名单为空只安装搜索入口；加入名单后才安装其余入口。磁盘游戏文件、GGPO、战斗计算和素材不修改。这仍属于进程注入与内存 hook。

安装 Python3.9+ 和32位 MinGW-w64 GCC/G++ 后执行：

```text
python build.py --cc i686-w64-mingw32-gcc --cxx i686-w64-mingw32-g++
```
