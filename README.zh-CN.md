# UNI2Blacklist

Windows GUI 黑名单插件，当前版本 `0.1.0-candidate.6`，适配本次更新 EXE 的候选版。按完整 SteamID64 过滤匹配候选、房间事件及 Steam 通信；原游戏 EXE 和 Steam DLL 的磁盘文件不改写。

用户已确认搜索拉黑生效，candidate.5 的玩家名和延迟恢复，但 Wi-Fi 全部未知。本轮修正把匹配设置中的 ID 错当成发布者 ID 的解析错误；发布者实际位于记录末尾。保留姓名、延迟和独立 Wi-Fi 排除选项。[原因与复现](docs/WIFI_IDENTITY_FIX.zh-CN.md)。candidate.2 旧闪退的具体根因仍未知；本轮验证范围不等同于真实游戏稳定性验收。[修正与未知点](docs/QUICK_MATCH_CRASH.zh-CN.md)、[验证范围](docs/VALIDATION.zh-CN.md)、[原生接口合同](docs/NATIVE_CONTRACT.zh-CN.md)。旧版本及下载保留，不建议继续用 candidate.2 重复触发该闪退。

本轮沿用已适配的新 EXE 指纹和场景 RVA `0x5A4A84`、五个匹配入口、动态排位观察、两分钟历史及退出诊断。连接类型与图标的分析见 [状态分类](docs/CONNECTION_STATES.zh-CN.md)。[EXE 适配证据](docs/EXE_UPDATE.zh-CN.md)。用户确认 Steam DLL 未更新，继续校验原 DLL 指纹。candidate.6 仅接受下方新版 EXE；旧版下载保留。

## 下载及使用

从仓库 Releases 下载 `UNI2Blacklist-0.1.0-candidate.6-win32.zip`，完整解压，不要在 ZIP 内运行。静态链接运行库，无需安装 Python。

1. **关闭旧黑名单窗口并重启游戏一次**；关闭 GUI 不卸载已注入 DLL，升级不能在同一游戏进程热替换。名单文件沿用。通过 Steam 正常启动游戏，运行 `UNI2Blacklist.exe`，选择进程并点击“连接并启用”。权限应与游戏一致。
2. 首次保持黑名单为空且不勾选“排除 Wi-Fi 玩家”进入快速匹配。此时应显示观察模式；新启动的进程 `hooks_ready=0`、`native_filter_active=0`、`effective_enabled=0` 正常，表示没有安装通信挂钩，**不表示安装失败**。仅搜索观察入口已接入。关闭保护开关也不进行过滤。
3. 窗口按游戏自然搜索结果显示玩家名、SteamID64、估计延迟、Wi-Fi／有线／未知和 LobbyID。名字来自游戏已经完成的本地缓存，按游戏使用的系统字符集解码。估计延迟来自已缓存的 Steam PingLocation；控制线程每100ms最多处理一位，每账号与房间至少间隔5秒再次读取，搜索回调不额外查询 Steam。缺字段、未初始化、解析失败或负估计均为“未知”。**该数值是 Steam 路径估计毫秒值，不是实测 RTT，也没有套用游戏内部的减28ms处理。RTT／丢包列已删除。**
4. 玩家最后一次被游戏搜索返回后在 GUI 保留 **120秒**。列表去重依据完整 SteamID64，保持行序和选中账号；“本次返回”与“最近出现”区分最新结果和历史行。历史行不代表玩家仍在待机，**不会重新写回游戏的匹配候选**。每次真实重现才延长保留时间，界面重绘不会延长。
5. 选中玩家点击“拉黑选中玩家”，或手动输入完整十进制 SteamID64 及备注。名单立即保存到 `%LOCALAPPDATA%\UNI2Blacklist\blacklist.tsv`。再次打开恢复名单。首次启用非空黑名单或 Wi-Fi 排除后，控制线程才安装房间及两套通信挂钩；控制周期约100毫秒。安装齐全并满足策略确认、心跳、非战斗条件后 `effective_enabled=1`。这是实现状态；用户此前确认的是 candidate.4 的实际搜索过滤，本轮 Wi-Fi 的真实联机拒绝仍待本机复验。
6. **“排除 Wi-Fi 玩家”默认不勾选**，之后单独保存到 `%LOCALAPPDATA%\UNI2Blacklist\options.ini`。勾选后，已观察且原字段为 Wi-Fi 的账号按同一候选／握手／发送／接收路径临时排除，**不加入 blacklist.tsv**。不确定类型放行；取消勾选后下个控制周期停用该规则（通常约100ms，受线程调度和接口调用耗时影响），仍保留明确拉黑的账号。临时分类最后真实出现后保留120秒，再次观察为有线／未知或同一账号多个房间数据冲突时解除临时分类。最多缓存4096个账号，满时丢弃最旧分类；该缓存只在当前游戏进程，不持久保存。
7. 移除账号、关闭总开关或关闭窗口会停止相应过滤；已经安装的挂钩仍保留并调用原函数，直到游戏退出。窗口异常退出后，GUI 心跳过期最多10秒后停止过滤。
8. 若游戏再次退出，**不必赶在退出前点击保存**。GUI 保留最后可用状态，自动写入 `%LOCALAPPDATA%\UNI2Blacklist\diagnostics\uni2-<PID>-status.txt`；同目录的 `uni2-<PID>-fault.bin` 是最多512字节的本地异常环形记录。仍可点击“保存诊断状态”导出包含异常信息的文本。自动保存失败会提示，可手动重试。

已有战斗（已查场景1）暂停拦截，对战中添加的名单用于后续匹配。历史列表最多2048人，满时保留现有未过期行并报告省略的新行；每次原搜索快照最多128人，过滤最多检查4096个原候选。

排位匹配玩家随游戏搜索结果动态变化；`candidate_count` 是本次捕获人数，`blacklist_count` 是本地已拉黑账号数。**匹配列表当前无人不停止观察，也不使已保存的黑名单失效。** 通信挂钩延后安装取决于是否启用了黑名单或 Wi-Fi 排除规则，而不是匹配候选人数为0。最近出现的历史行只便于选择，不能当作当前等待池。

## 诊断含义

- 报告区分界面请求开关、原生入口过滤、完整保护，以及 `connected`、`snapshot_source`。游戏退出后保留旧安装位，但两个有效保护字段强制为0，不能把旧状态当作当前保护。
- `hooks_ready` 是已经安装的通信接口位掩码：1=旧 P2P，2=Messages002，3=两者。首次黑名单为空且未勾选 Wi-Fi 排除时应为0；曾添加名单后清空，位可以仍为3，但有效过滤为0。
- `exclude_wifi` 是当前 Wi-Fi 规则开关，`wifi_cache_count` 是当前临时分类数量；`ping_queries` 是背景线程实际读取缓存 PingLocation 的次数，`ping_known_count` 是当前快照有估计值的人数。没有玩家身份明文。
- connection_wired_count、connection_wifi_count、connection_unknown_count 是当前快照的三类人数（最多128），不输出账号或原数据。
- 报告含 PID、搜索次数、最后场景、进程退出码，以及本地异常代码、指令地址、故障地址、线程、阶段和可识别模块名/RVA。模块缓存来自连接时，晚加载或动态代码可能只显示地址与分配基址。
- 异常记录是**第一时间观察到的异常，未必致命**；记录后总继续原异常分发，不恢复故障、不吞掉异常，也不替换游戏的异常处理器。最近8条循环覆盖，不包含堆转储、完整寄存器、堆栈内容或玩家账号。强制终止、部分 fail-fast、栈损坏及记录文件失败可能没有异常条目；没有条目不代表没有崩溃。
- 诊断文本不输出名单账号、玩家名、IP；连接错误可能含本机路径。全部数据只存本地，插件没有日志上传功能。本项目不修改注册表、Windows 防火墙或系统错误报告设置。

## 过滤边界

Wi-Fi 是原游戏按活动网卡类型生成、由对方通告的值，不是插件根据 IP 探测。游戏会优先采用遍历中遇到的第一块活动以太网／802.11网卡；双网卡、手机共享、桥接、VPN等可能与实际出口不同，不能保证检测真实物理链路。仅在游戏搜索观察过的账号上执行 Wi-Fi 排除，未观察的被动来访账号不会仅凭猜测拒绝。

搜索仍受原游戏区域、距离、模式和数量限制，不能保证显示全部在线或待机玩家。按账号而非全系统 IP 拦截；Steam 中继 IP 可能共享。丢弃黑名单消息的计数不是网络丢包率。

忽略 entered 事件不会强踢 Steam 后端房间里的玩家，对方可能占用槽位直到原清理或超时。名单在已有确认/握手后添加不会撤销已发生的界面切换；所有匹配模式是否能在确认阶段前拒绝仍待用户实测。与 uniGGPO 等其他注入插件同时运行尚未验证。

支持的版本固定为：

| 文件 | SHA-256 |
| --- | --- |
| `uni2.exe`（6,921,216字节，PE32） | `4ebed985ecbf330ab8e495573361e49df20bb555263289d1aff5425fac9b7ed9` |
| `steam_api.dll` | `67ae11d71ae6ec404090094df1e47b614d27400dc53fa450023e6fbcf347902c` |

其他版本拒绝连接；已改动的游戏入口会被签名校验拒绝。

## 原理及构建

GUI 核验目标文件与运行映像，在目标进程调用 Windows `LoadLibraryW` 加载 DLL、调用 `BlacklistStart` 初始化；同用户本机共享内存与互斥量传递策略和候选快照。原搜索调用完成后，搜索挂钩在同一生产线程、原 completion 回调之前检查快照；只有确有被规则排除的候选时才压缩游戏可见索引。候选缓存放在堆上，额外处理与原游戏调用分开。

原游戏入口及旧 P2P 使用固定版本 MinHook，保留原函数 trampoline；现代 Messages002 原子替换原虚函数表的 slot0/1/2，保留原表、RTTI、其他公开/隐藏方法和各原函数。页权限恢复、比较交换、部分回退和归属检查失败时锁存错误并停止过滤。本轮首次没有过滤规则只安装搜索入口；加入名单或启用 Wi-Fi 排除后才安装其余入口。IPC ABI 为3，旧 GUI／DLL不能混用。磁盘游戏文件、GGPO、战斗计算和素材不修改。这仍属于进程注入与内存 hook。

安装 Python3.9+ 和32位 MinGW-w64 GCC/G++ 后执行：

```text
python build.py --cc i686-w64-mingw32-gcc --cxx i686-w64-mingw32-g++
```

产物：`build/UNI2Blacklist-0.1.0-candidate.6-win32/`。GitHub 和发布包不包含原游戏文件、资源、实际个人日志、名单或凭据；按用户要求不发布测试集。代码采用 MIT，MinHook 保留许可证和来源指纹。
