# UNI2Blacklist

Windows GUI 黑名单插件，当前修复候选版 `0.1.0-candidate.2`。在本机向正在运行的 32 位 UNI2 注入 DLL，按完整 SteamID64 过滤匹配候选、房间事件及 Steam 通信。原游戏 EXE 文件不改写。

**这是需要本机匹配验证的候选版。** 已实现 GUI 和实际拦截路径，云端未运行原游戏，也没有证明所有联机模式都能在确认界面前拒绝对方。[验证范围](docs/VALIDATION.zh-CN.md)和[原生接口合同](docs/NATIVE_CONTRACT.zh-CN.md)分别记录验证结果与已知边界。

## 本轮修复

旧版实测报告显示候选已读取、旧 P2P 安装成功，现代 Messages002 安装失败，全部过滤停用。旧版没有细分错误，因此不能确认是函数入口、MEM_IMAGE 验证或 MinHook 的哪一步失败。新版现代接口改用槽位指针接入，避开入口反汇编及 MEM_IMAGE 限制；可执行的运行时 thunk 继续由原函数处理。页权限改动与恢复都检查返回值，槽位修改使用比较交换，部分失败只回退本插件仍持有的指针；缓存或槽位更换则明确停用。真实 Steam 客户端仍需用户复验。[本轮修复记录](docs/HOOK_FIX.zh-CN.md)。旧版和旧下载保留。

## 下载及使用

从仓库 Releases 下载 `UNI2Blacklist-0.1.0-candidate.2-win32.zip`，完整解压，不要在 ZIP 内直接运行。程序静态链接运行库，无需安装 Python。

1. **从旧版升级时先关闭旧黑名单窗口并重启游戏一次**，旧 DLL 不可在同一游戏进程热替换；名单文件沿用。通过 Steam 正常启动游戏。运行 `UNI2Blacklist.exe`，选择进程，点击“连接并启用”。权限应与游戏相同；游戏以管理员运行时，插件也需要相同权限。
2. 进入游戏联机菜单，正常执行搜索。窗口显示**游戏当前搜索返回的候选**，包括玩家 Steam 原文名字、SteamID64、LobbyID 和可取得的路径估计延迟。插件不另发全局扫描，不改变原搜索过滤器。
3. 选中玩家，点击“拉黑选中玩家”；也可以手动输入完整十进制 SteamID64，填写备注后添加。名单立即保存到 `%LOCALAPPDATA%\UNI2Blacklist\blacklist.tsv`。再次打开程序会恢复名单。
4. 候选表在下次游戏自然刷新搜索结果时重新过滤。已加入黑名单后，新加入房间、聊天握手、发送、接受会按名单拒绝。名单更新有约 100 毫秒控制周期。
5. 窗口顶部显示搜索次数和拦截计数。双通信接口安装齐全后显示“已接入”；显示“等待接口”时，候选和房间过滤已安装，但通信保护尚未齐全，不能视为完整保护。
6. 移除名单或取消“启用黑名单”可停止相应拦截。关闭窗口会停止保护，DLL 保留至游戏退出；窗口异常退出则最多 10 秒后自动停止过滤。更新插件包需要先重启游戏。

已有战斗（已查全局场景值 `1`）暂停拦截：对战中添加名单会保留当前比赛，下一次匹配使用新名单。此场景判断仍需真实 Windows 对局验证。

## 数据含义与限制

- 玩家名来自 Steam 缓存，缓存未取得时显示“未知”。身份判断始终用 SteamID64；重名、改名不会改变名单。
- “路径估计延迟”是原房间发布的 PingLocation 经 SteamNetworkingUtils 计算的毫秒估计，**不是当前对手的实测 RTT、带宽或游戏内部延迟等级**。
- 实际 RTT、丢包率当前显示“未知 / 未测”。“丢弃黑名单消息”计数是策略主动丢弃的消息数量，不能当成网络丢包率。
- 搜索结果受原游戏的区域、距离、房间人数、模式及数量限制，不能保证列出所有在线或待机玩家。窗口最多展示 128 个候选；后台过滤检查最多 4096 个原候选，超过边界保留原结果并记录错误。
- 使用账号过滤而非全系统 IP 防火墙规则。Steam 中继 IP 可能共享，无法可靠代表某个玩家；本版不修改 Windows 防火墙，也不承诺阻止 Steam 后端所有数据包到达机器。
- 忽略被拉黑玩家进入事件，**不会强制将其踢出 Steam 后端房间**。对方可能继续占用房间槽位，直到原游戏或 Steam 的退出、超时清理。匹配推进速度和确认界面出现与否，仍需用户实测。
- 名单在已有确认、握手或战斗开始后添加，不会撤销已经发生的界面切换。联机菜单打开前连接、并在新搜索前设置名单，可以覆盖已实现的最早过滤入口。

支持的游戏指纹固定为：

| 文件 | SHA-256 |
| --- | --- |
| `uni2.exe`（6,921,216 字节，PE32） | `cf64ec26e9646b68b46ed22c838b8f0778ab65abbeda0ebf164e81b5c08c9098` |
| `steam_api.dll` | `67ae11d71ae6ec404090094df1e47b614d27400dc53fa450023e6fbcf347902c` |

其他游戏版本拒绝连接，不根据相似地址猜测。已修改的 hook 入口也会被签名校验拒绝。与 uniGGPO 等插件同时注入尚未验证。

“保存诊断状态”输出本地文本，包含构建版本、指纹、场景、接口安装状态、名单数量和拦截计数；不输出名单账号、玩家名或 IP。新版报告将 `requested_enabled`（界面开关）、`native_filter_active`（已实现入口正在过滤）、`effective_enabled`（两套接口齐全、策略已确认且心跳有效的完整保护）分开；空名单不会产生拒绝计数。`hooks_ready` 是已安装接口位掩码：1=旧 P2P、2=Messages002、3=两者；失败后的已安装位不代表保护仍有效。报告新增各组安装方式、失败阶段、MinHook/Win32 错误、槽位、内存类型、模块名与 RVA、目标入口的最多16字节及回退错误。仅含本机代码地址，模块只输出文件名；连接错误可能带本机路径，请自行查看后再分享。插件没有联网上传功能。

## 原理

GUI 枚举已运行的游戏，并核验文件和运行映像。随后在目标进程调用 Windows `LoadLibraryW` 加载本项目 DLL，调用 DLL 的 `BlacklistStart` 初始化。控制与候选快照经同用户的本机共享内存和互斥量传递。

原游戏入口和旧 P2P 用 MinHook 改写少量内存函数入口，保留原函数 trampoline。现代 SteamNetworkingMessages002 通过原虚函数表的 slot 0、1、2 原子替换指针，保留各槽位的原函数；不复制或截短具体类的表，不改动其 RTTI、其他公开方法或内部方法。此表可能由多个同接口实例共享。允许的玩家调用原函数；被拉黑玩家返回失败或忽略相应回调。搜索过滤发生在**原生产搜索结果的线程**，原 completion 回调之前，只压缩可见候选索引，不创建伪玩家或伪搜索结果。两套通信接口的发送、接受和接收均覆盖，因为发送本身也能隐式接受连接。

这属于进程注入和内存 hook，程序不仅是只读内存查看器。磁盘 EXE 和 Steam DLL 不改动，也不改 GGPO、战斗计算或游戏素材。

## 构建

安装 Python 3.9+ 和 **32 位 MinGW-w64 GCC/G++**：

```text
python build.py --cc i686-w64-mingw32-gcc --cxx i686-w64-mingw32-g++
```

产物位于 `build/UNI2Blacklist-0.1.0-candidate.2-win32/`。源码不依赖 Steamworks SDK 安装，也不包含原游戏二进制、资源、个人名单、日志或凭据。按用户要求不发布测试集；验证结果保存于说明文档。

项目代码采用 MIT；固定版本 MinHook 保留其许可证和来源指纹。
