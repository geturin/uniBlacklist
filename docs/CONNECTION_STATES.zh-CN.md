# 连接类型、信号及图标分类调查

2026-10-08。使用本次新版 EXE，SHA256 `4ebed985ecbf330ab8e495573361e49df20bb555263289d1aff5425fac9b7ed9`，REA/Ghidra 12.1.4、x86 指令检查及原序列化机器码的 Unicorn 隔离执行。没有启动原游戏，没有向真实玩家探测。资源检查使用环境中已有 build-25179931 归档；尚未取得用户更新后的完整资源，不能把旧资源图样视为新版客户端的实际截图。

## 能确认的分类

| 维度 | 状态 | 含义和限制 |
| --- | --- | --- |
| 网卡通告 | 原值0＝有线；1＝Wi-Fi | 独立于信号格数。来源是对方客户端的活动网卡分类，不是接收信号强度或 RTT 识别 |
| 插件无法分类 | 未知 | 缓存缺失、未满足格式／长度／账号绑定、非法值或读取失败。与原值0不同；Wi-Fi 排除放行未知 |
| 游戏信号档位 | 内部1–5对应从弱至强的五档，可呈现0–4格 | 根据游戏自己的时间量分档；并非无线网卡 RSSI。“有线4格”和“Wi-Fi4格”完全可以同时存在 |
| 尚未测到信号 | 部分列表路径写内部0，使用未知提示 | 不应把它换算成0ms；要与最低信号档区分 |
| 自己的账号 | 列表路径对本人写内部6 | `0x7c2270` 先比较本人的 SteamID64，不对本人使用远端测量档位。不能拿本人图标评估对端网络 |
| 其他图标变化 | 独立图形、样式或提示维度 | 已确认有额外 `network_icon_fpslevel_steam` 资源，但本轮未建立全部图形到运行状态的选择合同。不能仅凭文件名把某一种不同图标认定为低 FPS、丢包或抖动 |

原 `0x4de070` 使用 `GetAdaptersAddresses`，只考察 OperStatus=Up；遍历中首次遇到 IfType=6 返回0，首次遇到 IfType=71返回1。它不根据当前 Steam 流量的默认路由挑选网卡；无匹配适配器或获取失败最终也是0。故本机同时启用有线与无线、手机 USB 共享或虚拟网卡时，通告可能不代表真实出口。这个分类值由客户端产生，没有“检测保证”或防伪校验。

## 信号档位的原始边界

函数 `0x5e0960` 接收整数时间量 q；原表 `0x9397b0` 为1600、3300、5000、8300、-1：

| q | 原返回档位 | 从弱至强对应 |
| --- | --- | --- |
| q≤0 | 0 | 无有效时间量；具体界面须区分未测到／未知 |
| 0<q<1600 | 5 | 最强，4格 |
| 1600≤q<3300 | 4 | 3格 |
| 3300≤q<5000 | 3 | 2格 |
| 5000≤q<8300 | 2 | 1格 |
| q≥8300 | 1 | 最弱，0格 |

这里列的是**原函数的输入单位和边界**，不把 q 直接标为毫秒。已查 `0x6b3a40`、`0x7c2270` 等路径先把内部时间值除以20再调用；其他路径还有取整差异。`0x4ef6b0` 的一条 Steam 估计路径又会先对正估计减28ms并至少保留1ms，再转成微秒。不同来源必须逐条连接，不能统一写成“4格必定小于某个实测 RTT”。本插件估计列直接显示 Steam 返回的毫秒值，不反算信号格数。

`0x5f7cd0` 将内部2、3、4、5映射到8、6、4、2，其他值返回 INT_MAX；`0x5f7c20` 的筛选档位0–4映射 INT_MAX、2、4、6、8。这是游戏自己的匹配筛选层，不是 Wi-Fi 标志。此轮不改这些原算法或阈值。

## “都是有线4格，但图标稍不同”目前能说到哪里

有线／Wi-Fi标志、延迟档位和附加图形是独立的，单看“四格有线”不能推出两个玩家的全部状态相同。但**本轮还不能给你所见的每种细微图标变化下确切定义**。

已查到：新版 `0x7898e9` 引用 `grpdat/Network/new/network_icon_fpslevel_steam`，加载结果写网络资源对象+`0x15c`；环境资源有独立64×64图集。原资源还有网络信号图集与独立段位／READY／WIN图集，它们不能互相当成网络质量指标。未上传图集或原资源。

另已查 `0x5d8d70`／`0x5d8f00` 统计时间样本均值、相邻差绝对值均值和缺样比例，写 `0x10bc948`、`0x10bc94c`、`0x10bc950`；`0x7cb2a0` 等路径把这些值带入网络状态对象。**尚未证明这些统计量决定了上述 Steam 图集的哪些图形。** 本轮不把它们作为匹配列表的 RTT／丢包读数，也不因此增加过滤规则。

继续查清需要：资源对象+0x15c的实际绘制消费者与纹理裁切／图形编号、编号各自的条件和上游字段、FPS或性能字段的生产与更新周期、用户所见变体所在的具体页面。已查候选路径 `0x7c2270`、`0x7c2b10`、`0x7c4d80`、`0x7cb2a0`、`0x7dd450`、`0x7e3730`、`0x6b3a40` 以及前述统计函数；未闭合的绘制映射保留为未知。

## 本轮实现范围

只把原网卡通告接入 Wi-Fi 列和独立排除选项。排位 CustomData1 直接解析，房间 CustomData1 先解长度前缀和嵌套 Base64；末尾发布者完整 SteamID64 要与当前行 owner 一致（排位0x7c／房间解码后0xc2）；candidate.5误用前一个账号0x1a／0x24导致全部未知，candidate.6纠正，见 [解析修正](WIFI_IDENTITY_FIX.zh-CN.md)。原值非法不默认当有线。只有已被游戏搜索观察的 Wi-Fi 账号进入两分钟临时缓存，未观察的被动来访者不会凭猜测分类。

信号格数、FPS图标、抖动及丢包条件没有新增 GUI 控件或过滤规则。未来可将这些作为分别可选的条件，但须先完成每种字段和图标的原生证据链。
