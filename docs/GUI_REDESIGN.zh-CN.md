# candidate.7 界面与请求记录

本轮只调整控制界面与本地显示。匹配入口、Wi-Fi 解析、原生过滤计数、注入与共享内存协议沿用 candidate.6；发布及实测结论以对应版本的验证记录为准。

## 主界面

默认窗口尺寸为 **880 × 620 逻辑像素**，允许调整大小。主界面保留进程选择、连接、过滤开关、玩家列表和黑名单；移除大段技术说明以及手动填写 SteamID64／备注的添加区。

使用顺序：

1. 启动游戏，点“刷新”，选择 `uni2.exe` 的 PID，点“连接”。
2. “启用拦截”默认勾选，按需勾选“排除 Wi-Fi”。没有名单且未排除 Wi-Fi 时只观察。
3. 在游戏的搜索结果中选中玩家，点“拉黑玩家”。在右侧黑名单中选中玩家，点“解除拉黑”。
4. 需要查看过滤活动时打开“请求记录”。

名单按账号保存，加入时使用已观察到的玩家身份；不需要事先知道 SteamID64。最近名单仍保留最后真实出现后的 **120 秒**，重新绘制界面不会延长保留时间，历史行也不会写回游戏的当前候选名单。

## 中文／English

语言选择即时更新窗口标题、按钮、列表列名、连接状态和请求记录窗口。程序标题分别为“UNI2 黑名单”和“UNI2 Blacklist”。首次启动默认中文，选择保存到 `%LOCALAPPDATA%\UNI2Blacklist\language.ini`，下一次启动恢复；这与 `blacklist.tsv`、Wi-Fi 的 `options.ini` 独立。

切换语言不重新连接游戏，不添加／移除名单，不更改过滤策略或 Wi-Fi 开关。错误提示按可用翻译显示；原始诊断文本保留，未识别的错误信息不会被隐藏。

## 请求记录窗口

记录来自游戏进程已经累计的四个原生计数：

| 界面动作 | 原生字段 | 含义 |
| --- | --- | --- |
| 跳过 / Skipped | `candidate_skips` | 从游戏可见搜索候选中跳过的条目 |
| 拒绝 / Rejected | `request_rejects` | 被策略拒绝的房间／握手等请求 |
| 拦截 / Intercepted | `send_rejects` | 被策略拦截的发送 |
| 丢弃 / Dropped | `receive_drops` | 被策略丢弃的接收／房间事件 |

控制窗口每 **500 毫秒**读取计数快照。每次观察中有变化的类型生成一行，显示“观察时间、动作、增加次数”；例如同一周期内拦截了 8 次发送，显示一行“拦截 +8”。最多保留最新 **200 条**。上方累计值来自当前游戏进程的原生计数，可能包含打开窗口前已经累计的数量；建立连接时用当前值作为基线，不把此前的累计值伪造成新事件。

记录表示控制窗口读到增量的时刻，**不是每个网络请求的精确发生时间**。它不包含玩家名、SteamID64、IP、端口或请求内容，也不能据此把某次拦截归给某个玩家。四类数量可能涵盖同一匹配过程的不同步骤，不能简单相加当作独立对手或独立对局数量；“丢弃”也不是测得的网络丢包率。

“清空记录”只删除展示行，不清零游戏累计计数、不重置采样基线、不改变名单或过滤策略。关闭记录子窗口后，主窗口继续采样和过滤，再打开可查看保留的记录。新连接到另一游戏进程时重新建立基线，避免把两次进程的计数相减；DWORD 计数回绕按无符号差值处理。

## 保留行为与验证边界

Wi-Fi 排除默认关闭，按现有规则临时过滤观察到的 Wi-Fi 账号，不加入永久名单；未知类型及未观察到的被动来访账号放行。已有战斗暂停拦截。名单与 Wi-Fi 设置沿用，不因界面改版而迁移或清空。

关闭主窗口仍停止过滤；关闭请求记录子窗口不会停止过滤。DLL 已加载后保留到游戏退出，所以升级必须关闭旧主窗口并重启游戏，再使用新包中配套的 EXE 与 DLL。

本说明描述界面与计数模型，不宣称已完成真实 Steam 联机、原生 Windows 画面／字体／DPI 或不同匹配模式的验收。构建、窗口操作、下载校验等具体结果写入本版本的验证与交付记录；本地最终使用效果由用户测试。
